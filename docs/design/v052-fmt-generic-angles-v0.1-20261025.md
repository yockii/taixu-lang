# fmt 规范形修订：泛型尖括号 v0.1（2026-10-25）

> 来源：跟进第 44、45、47、56 条。只改 `taixu fmt` 的行内空白规则，不改语法与语义；兼容变更 `tool.fmt-generic-angles`。

## 一、缺陷

- fmt 是纯词法的保守格式化器（D2 §9／D9），只在 `Ref`、`Weak`、`List` 之后把 `<` 认作类型尖括号，且开括号之后没有紧贴规则：
  全仓通行的 `List< int>`、`Ref< Node>` 是这个缺陷的产物（代码注释的本意是 `Ref<T>` 收口紧贴，Zig 时代的 fmt 同样如此）。
- 其余泛型被当成比较运算排开：`Map< string, int>` 排成 `Map < string, int >`，`Future<int>` 在形参与返回类型顶层排成
  `Future < int >`，显式类型实参的调用 `wrapTo<i32>(x)` 排成 `wrapTo < i32 > (x)`，泛型结构体声明 `struct Box<T>` 排成
  `struct Box < T >`——同一种东西三种写法。
- D3、llm-guide、SKILL 的示例一律写 `List<int>`：照指南写的代码过不了 `fmt --check`，AI 生成的代码首当其冲。
- 另：`for (x in [1, 2])` 排成 `in[1, 2]`（`in` 是上下文关键字，词法上是标识符，后接 `[` 按下标处理）。
- 另：`??` 合并运算排成 `a?? b`（D3 v0.12 起登记为“token 间距美观项、不阻断”），其后的负号当成双目：`a ?? -1` 排成
  `a?? - 1`。`??` 是两个 `?` 记号（解析器以双 `?` 前瞻解糖），fmt 把每个 `?` 都当后缀紧贴前文、并算作表达式结尾。

## 二、方案比较

| 方案 | 做法 | 取舍 |
|---|---|---|
| A. 按名字表认 | 内建泛型类型名之后的 `<` 认作尖括号 | D3 v0.13 起有用户泛型结构体与泛型函数，名字表不封闭，认不全，不取 |
| B. 接解析结果 | fmt 先解析，按 AST 的类型位置认 | 精确，但 fmt 现只拒词法错误、语法错误的文件照样能排；接解析要么拒更多输入，要么两套路径，不取 |
| C. 与解析器同一前瞻规则（**采用**） | 标识符之后的 `<`，往后只经过标识符、整数、逗号、`?`、`|`、方括号与嵌套尖括号到达配对的 `>`，且其后是 `(`、`{` 或类型之后才有的记号（`,` `)` `=` `;` `>` `?` `|` `]` `}` `=>`、文件尾） | 解析器自己就是按这条词法前瞻消歧的（`parser.tx` 的 `genericArgsAhead`：`f<int>(x)` 是调用、否则 `<` 恒为比较），fmt 与它一致即不会把比较排成泛型；比较运算到不了配对的 `>`（`i < n)`、`a < b && …`），或 `>` 之后紧跟操作数（`f(a < b, c > d)`） |

规范形取 `List<int>`、`Map<string, List<int>>`、`wrapTo<i32>(x)`、`struct Box<T>`、`function f<T, U>(…)`：尖括号两侧与内侧都紧贴、
类型实参之间逗号后一空格——同 Rust、TypeScript、Java、C#、Swift、Kotlin 的官方格式化器。源中零空白相邻的 `<<` 仍是移位。

`??` 同其他双目运算两侧一空格、两个问号紧贴：`a ?? b`、`a ?? -1`（同 C#、TypeScript 的 `??`，Swift 的 `??`，Kotlin 的 `?:`）。
认定同解析器：后缀位置的 `?` 之后紧跟（穿透注释）另一个 `?` 即为一对，自左向右成对；第二个 `?` 不算表达式结尾（其后的
负号是一元的，行尾停在 `??` 也不补分号）。`T?`、`f()?` 不变。

## 三、改动

- `bootstrap/selfhost/fmt.tx`：`markAngles` 预先逐 token 标出泛型尖括号、for 头的 `in` 与 `??` 对；`inlineSpace` 据此紧贴或留空，
  去掉 `typeAngle` 计数与 `Ref`／`Weak`／`List` 名单。
- 全仓重排：fmt 守护的目录（examples、tests/cases、skill/taixu/examples、docs/design、bootstrap、spike）与标准库 src、tests；
  `.zcode` 的 skill 副本同步。`git diff -w` 为空：改动只有记号之间的空白（字符串、模板串、字符字面量与注释由 fmt 原样输出）。
- fmt 夹具：三个把旧排法写成期望的金标准改为新规范形，新增 `generic-angles`（声明、嵌套、调用、结构体字面量、可选与联合、
  比较、移位、实参里的比较、for-in 数组字面量）与 `coalesce`（`??` 紧贴与松散的写法、连用、其后的负号与 `!`、`T?`、`f()?`）。
- 前端冻结清单 `--update`：变化的 157 项输出全部属于被重排的 56 个输入文件，没有输入未变而输出变化的项。

## 四、影响

- 只改空白，语法树、诊断的种类与文案不变；诊断的列号随空白移动。
- 用户已按旧排法格式化的代码在新版 `fmt --check` 下报需要格式化，`fmt --write` 一次即可。

## 五、补记（2026-10-26）：生成器声明的星号

`function* 名`（D3 v0.22 §6.20 的写法，同 JS／TS 常见格式化器）原被当作双目乘号，排成 `function * 名`——仓库里的生成器用例
都写 `function*`，`fmt --check` 因此报需要格式化。`inlineSpace` 加一条：紧跟 `function` 的 `*` 紧贴，其后照常一空格；乘号不变
（`a*b` 仍排成 `a * b`）。fmt 夹具新增 `generator-star`；并入兼容变更 `tool.fmt-generic-angles`（同属未发布的 0.2.24-dev 规范形
修订）。
